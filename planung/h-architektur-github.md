# h) Architektur zur GitHub-Variante

1. **Key-Schutz: Cloudflare Worker.** Gratis (100.000 Anfragen/Tag). Secret `TMDB_TOKEN`. Nur GET, feste Pfadliste (discover/movie, movie/{id}, movie/{id}/recommendations, person/{id}/movie_credits, search/movie|person|company, company/{id}, genre/movie/list, configuration), sonst 403. CORS nur Pages-Adresse + localhost. Ehrlich: CORS hält Kommandozeile nicht ab; Schaden auf lesende TMDB-Abfragen begrenzt, Key bleibt geheim.
   Verworfen: Supabase Edge Function (Gratis-Projekt pausiert nach 1 Woche ohne Nutzung); Netlify/Vercel (zweites Hosting); Key pro Gerät (für Clubmitglieder unbenutzbar); Key öffentlich (gegen Anforderung/TMDB-Bedingungen).
2. **Profile nur im Browser:** `localStorage` Schlüssel `filmapp.v1`, Datenmodell wie PLAN.md + `lastBackup`; einige hundert KB. Sichern/Laden als JSON (einzeln oder alle). Verworfen: gemeinsamer Speicher mit Club-Code (kein echter Schutz, doppelter Aufwand, Konflikte) – Extra für später.
3. **iOS-Löschregel ernst:** 7 Safari-Nutzungstage ohne Besuch → Daten weg. Gegen: (a) Web-App auf Home-Bildschirm (manifest.webmanifest + Icon); FALLE: Home-Bildschirm-App hat eigenen Speicher getrennt vom Safari-Tab → zuerst installieren, dann markieren, oder per Sicherung umziehen; (b) `navigator.storage.persist()`; (c) Hinweis „Jetzt sichern" wenn letzte Sicherung > 14 Tage und ≥ 20 Markierungen.
4. **Zwischenspeicher:** Browser: Map im Speicher, 6 parallel. Worker setzt `Cache-Control: max-age` je Pfad (7 Tage / 1 Tag / 1 Std.) → Browser-HTTP-Cache über Neustarts. Verworfen: Cache API im Worker (auf *.workers.dev wirkungslos).
5. **Veröffentlichen:** Nutzerin: TMDB-Token, Cloudflare-Konto, `npx wrangler login` bestätigen, `npx wrangler secret put TMDB_TOKEN` im eigenen Terminal, Key in `worker/.dev.vars`, Repo/Pages-Anlage bestätigen. Claude: `gh repo create` (nach OK), git push, Pages (main, /docs), `wrangler deploy`, Worker-URL in `docs/js/config.js`. Schutz: .gitignore (.dev.vars, .env, node_modules), `.dev.vars.example`, `npm run check-secrets` vor Push (Muster `eyJ`), GitHub Push-Schutz.
6. **Lokal:** `npm start` → `scripts/dev.js`: prüft node_modules/.dev.vars, startet `wrangler dev` (8787) + Mini-Webserver node:http für docs/ (5500). Einzige Dev-Abhängigkeit wrangler. Verworfen: concurrently/http-server.
7. **Struktur:** docs/ (index.html, style.css, manifest.webmanifest, icons/, tmdb-logo.svg, js/ app config tmdb store backup recommend surprise seeds), worker/ (index.js, wrangler.toml, .dev.vars.example), scripts/ (dev, check-tmdb, check-secrets), package.json, .gitignore, README.md.
8. **Bauschritte:** 0 Nutzerin: Konten. 1 Gerüst lokal. 2 früh veröffentlichen (Worker, Secret, Repo, Pages, check-secrets, check-tmdb gegen echten Worker; fertig wenn Link am iPhone über Mobilfunk leere App zeigt und fremder Pfad 403; Halt). 3 Profile (localStorage, Sichern/Laden, persist, Manifest, Home-Hinweis). 4–7 wie PLAN.md, nach jedem Schritt push + Test am Link. 8 Über-Seite, README, Abnahme.
   Abnahme neu: läuft per Link + lokal `npm start`; Browser schließen/öffnen → alles da; Sichern/Laden hin und zurück; Key nicht im Repo, check-secrets still; Worker lehnt fremde Pfade ab.
